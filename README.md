# Театральный гид по Москве — публикация сайта

В этом комплекте находится актуальная версия лид-магнита Горбилета.

## Файлы

- `index.html` — весь сайт. Внутри уже есть оформление, шрифты, логотипы, анимация кулис, подбор спектаклей и UTM-ссылки.
- `.nojekyll` — пустой служебный файл: позволяет публиковать готовый HTML без обработки Jekyll.
- `README.md` — эта инструкция.

Отдельно загружать шрифты, логотипы, Excel, исходный драфт или устанавливать программы не нужно. Для просмотра на компьютере можно открыть `index.html` двойным щелчком.

## Публикация через браузер

1. Распакуйте архив `theatre-moscow-github-pages.zip` на компьютере.
2. Войдите в свой аккаунт на [GitHub](https://github.com/).
3. Нажмите **+ → New repository**. Укажите название `theatre-moscow`, выберите **Public**, включите **Add README** и нажмите **Create repository**. Для этого способа подходит бесплатный аккаунт с публичным репозиторием.
4. В новом репозитории откройте **Code → Add file → Upload files**.
5. Перетащите три файла из распакованного архива в область загрузки. Загружайте сами файлы, а не ZIP и не папку целиком: `index.html` должен лежать непосредственно в корне репозитория. Загруженный `README.md` заменит созданный на предыдущем шаге.
6. В поле описания напишите `Добавить театральный гид`. Сохраните файлы в ветку **main** через **Commit changes**. Если GitHub предлагает новую ветку, выберите сохранение непосредственно в **main** для этого нового репозитория.
7. Откройте **Settings → Pages**.
8. В **Build and deployment** установите **Source: Deploy from a branch**.
9. Выберите **Branch: main**, папку **/(root)** и нажмите **Save**.
10. Дождитесь публикации. Это может занять до 10 минут. На странице **Settings → Pages** появится адрес сайта и кнопка **Visit site**.

Адрес будет иметь вид `https://ВАШ-ЛОГИН.github.io/theatre-moscow/`, где `ВАШ-ЛОГИН` — имя вашего аккаунта GitHub. Это пример формата адреса, фактическую ссылку скопируйте из **Settings → Pages**. Её можно отправлять в рассылке; посетителям не нужен аккаунт GitHub.

Официальные инструкции: [создание и запуск GitHub Pages](https://docs.github.com/en/pages/quickstart), [настройка ветки публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [загрузка файлов](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## Проверка после публикации

- Откройте адрес сайта на компьютере и телефоне.
- Проверьте раскрытие кулис, выбор настроения, карточки рекомендаций и подбор по трём вопросам.
- Откройте несколько кнопок «Смотреть билеты»: в адресе страницы Горбилета должны быть `utm_source=vk`, `utm_medium=rassilka_msk`, `utm_campaign=lead_spektakl` и `utm_content` с названием выбранного спектакля.
- Сравните актуальные даты и цены с Горбилетом перед рассылкой. В этом HTML они заданы вручную и автоматически не обновляются.

## Как обновлять сайт

После следующих правок снова откройте **Code → Add file → Upload files**, загрузите новый `index.html` с тем же именем в корень репозитория и сохраните в **main**. При такой настройке GitHub Pages опубликует изменения по прежнему адресу. Если браузер показывает старую версию, обновите страницу через **Ctrl + F5**.

## Если сайт не открылся

- Подождите до 10 минут после сохранения настроек или файлов.
- Убедитесь, что в корне репозитория лежит именно `index.html`, а не архив или папка с ним.
- Проверьте настройки **main → /(root)** в **Settings → Pages**.
- Если публикация завершилась с ошибкой, откройте вкладку **Actions** и последнюю задачу публикации Pages: там будет причина.

## Что сохранено в этой версии

Лёгкое раскрытие кулис; первый экран без количества спектаклей и площадок; выравнивание карточек рекомендаций и плашек; защита от переноса отдельных букв и коротких предлогов; исходные ссылки Горбилета с добавленными UTM-параметрами. Нижняя кнопка «Выбрать спектакль» ведёт к рекомендациям, а три ссылки на жанровые каталоги — на Горбилет.
